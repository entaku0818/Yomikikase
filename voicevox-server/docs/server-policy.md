# TTSのキャラと上限をサーバーで管理する

初期値の正本は `internal/policy/default.json`。iOS/Androidにキャラ一覧・文字数・モデル・追加パック付与数を複製しない。
既存VOICEVOXの無料5,000字/有料200,000字はそのまま。Geminiの月3,000字と追加パックは別枠の準備値で、現在は無効。

## 次のアプリバージョンとの接続

1. **先にサーバーを更新**し、`GET /v1/config` と新形式の `GET /v1/voices` が200を返すことを確認する。
2. 次のiOS/Androidは再生開始のたびに設定を取得し、`voicevox.maxRequestChars` で文章を分割する。月の残量は従来どおり `/v1/quota` と生成応答で表示する。
3. iOS購入画面も設定APIの月上限を表示する。取得失敗時は固定の古い数字を表示しない。各ストアの購入金額は引き続きStoreKit/Play Billingから取得する。
4. その後にアプリを配信する。旧版の分割値・宣伝文は固定のままなので、初回移行では既存の上限を維持する。旧サーバーは設定APIがないため、新アプリを先に出すとキャラ音声の生成が停止する。

端末の分割と表示は補助であり、許可・上限・使用量の最終判断は常にサーバー。クライアントが送った上限や残量を信用しない。同じサーバー利用者IDに対して、端末の表示上限を増やしても許可枠は増えない。本人認証の課題は後述のとおり別に残る。設定取得に失敗したとき、アプリは新規生成せず既存の失敗イベントで端末音声への切替を案内する。保存済み音声の再生自体は課金しないが、今回のバージョンは再生開始時に設定APIへの接続を必要とする。

## 変更方法

- 環境変数なし: 埋め込みの `default.json` を使用。変更にはサーバー再デプロイだけが必要。
- `TTS_POLICY_FILE=/absolute/path/policy.json`: リクエストごとにファイルを再読込。検証後に一時ファイルからrenameして置換する。手元での検証向け。
- `TTS_POLICY_DOCUMENT=tts_policy/current`: Firestoreの同文書の `json` フィールドに保存したJSON文字列を毎回読み込む。稼働中の全インスタンスに次のリクエストから反映。アプリ更新・サーバー再デプロイは不要。ファイルとの併用は禁止。

Firestoreの導入手順（**まだ本番には適用していない**）:

```sh
cd voicevox-server
# ローカル検証。クラウド書込みなし
go run ./cmd/policy -file internal/policy/default.json
# 管理者のADCで初回登録。プロジェクト名を必ず明示する
go run ./cmd/policy -file internal/policy/default.json -project voiceyourtext -expect-revision absent -publish
```

Firestoreルールでは `tts_policy/{document=**}` のクライアント読書きを許可しない。他の広いallowルールがあると個別denyでは打ち消せないため、既存ルールも確認する。サーバーはIAM経由で読込み、設定更新は管理者のIAMに限定する。この条件と初期文書を確認してからCloud Run gatewayコンテナに `TTS_POLICY_DOCUMENT=tts_policy/current` を設定する。

以後はJSONの `revision` を新しくして、変更前revisionを指定して発行する:

```sh
go run ./cmd/policy -file policy-next.json -project voiceyourtext -expect-revision 2026-10-30.2 -publish
```

発行はトランザクションでrevisionを比較し、同時編集による上書きを拒否。`tts_policy/current/revisions/{revision}` に履歴を作る。戻すときも過去の値に新revisionを付けて発行する。文書が不正・消失・読込失敗なら503 `policy_unavailable` で新規生成を止め、既定の大きな枠へ戻さない。生成前の設定スナップショットで予約済みの処理は旧設定で完了し、次の生成から新設定となる。上限を使用済み文字数より下げた場合、残り0となり追加生成を拒否する。設定変更は使用量をリセットしない。

`enabled=false` で新規VOICEVOX生成を停止できる。設定APIは公開されるが、返すのはVOICEVOXの表示・分割用の値のみ。原価・モデル名・未発売商品は返さない。モデル変更、原価上限、リトライ数、追加パック付与数はサーバー内の非公開設定に置く。

## キャラの追加・表示順・公開停止

`catalog` も上限と同じ設定文書で管理する。現在は既存の6キャラを移したもので、新しいキャラを追加したわけではない。

- `voices`: 配列順がアプリの表示順。各要素に `speakerId`（エンジンのスタイルID）、`character`、`style`、`credit`、`termsUrl`、`enabled` を設定する。
- `defaultSpeakerId`: 初回選択と公開停止時の切替先。公開中のIDを指定する。全員を非公開にする場合は `null` にする。
- `termsUrl`: VOICEVOX全体の規約URL。各キャラの規約URLと合わせてHTTPSのみ許可する。
- キャラを公開停止する場合は削除せず `enabled: false` にする。選択肢と新規生成から外れ、過去の音声に必要なクレジットは残る。
- 新規追加前に、稼働中のエンジンがそのスタイルIDに対応することと、商用利用・申請・クレジット等の条件を確認する。任意の名前だけで新しい音声モデルが生まれる仕組みではない。

`GET /v1/voices` は `schemaVersion: 1`、`revision`、`defaultSpeakerId`、`termsUrl`、選択可能な `voices`、非公開分も含む `credits` を返す。全体の `voicevox.enabled` がfalseなら選択肢は空、既定の声はnullとなる。生成APIも同じ設定からIDを検証するため、旧アプリや直接のAPI呼出しでも非公開キャラの新規生成はできない。

iOS/Androidは選択画面を開いたときと再生開始時に取得する。保存したIDがなくなっていればサーバー指定の既定の声に切り替える。取得・検証に失敗した場合は固定の一覧へ戻さず、新規生成を止める。クレジット画面では最後に検証できた一覧を端末に保存して通信失敗時にも表示する。公開停止したIDを別のキャラに使い回さないこと（保存済み音声のキャッシュはIDで識別する）。

## Gemini・追加購入の未実装部分

Geminiの実生成、原価上限に基づく予約/精算、Firebase Auth等の検証済みユーザーID、ストア検証と追加購入台帳は未接続。このサーバー版はGemini/追加パックの `enabled=true` を検証エラーにし、設定だけで未完成の課金を有効化できないようにしている。従来のApp Check + X-User-IDは購入者本人の認証ではないため、有料AI枠/追加パックには流用しない。

追加購入の実装時は、サーバーがストア商品IDから付与量を決定し、検証済みの取引IDにつき一度だけ付与する。端末からの付与文字数は受け付けない。使用量超過は停止して追加購入を案内し、自動で超過課金しない。利益試算はentaku-hqの `docs/finance/narrator-tts-2026-10-30.md` を参照する。
